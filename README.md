# Mitsubishi AC (ECHONET Lite) — Homey App

A [Homey](https://homey.app) app that discovers and controls **Mitsubishi Electric
air conditioners / heat pumps** over your local network using the
[ECHONET Lite](https://echonet.jp/english/) protocol — no cloud, no MELCloud account.

It talks directly to the Wi-Fi interface adapter fitted to the indoor unit
(**MAC-558IF-E / MAC-567IF-E / MAC-568IF-E / MAC-578IF-E / MAC-588IF-E**), using
the standard *Home air conditioner* device class (ECHONET class group `0x01`,
class `0x30`).

## Features

| Capability | ECHONET property | Notes |
|---|---|---|
| On / off | `0x80` | |
| Mode | `0xB0` | Automatic, Cooling, Heating, Dehumidify, Fan only |
| Target temperature | `0xB3` | 16–31 °C (whole degrees per the protocol) |
| Room temperature | `0xBB` | Read-only, signed |
| Outdoor temperature | `0xBE` | Read-only (sub-capability) |
| Fan speed | `0xA0` | Auto, Quiet, Low, Medium, High, Maximum |
| Vertical vane | `0xA1 / 0xA3 / 0xA4` | Auto, Top, Upper, Middle, Lower, Bottom, Swing |

State is read back from the unit on a configurable poll interval (default 60 s),
so changes made with the IR remote or MELCloud are reflected in Homey, and all
capabilities are available as Flow cards (triggers, conditions and actions).

## Prerequisites

1. A supported Mitsubishi Wi-Fi adapter connected to your LAN.
2. **ECHONET Lite enabled on the adapter.** In the *MELCloud* / *Mitsubishi
   Wi-Fi* app, open the device settings and turn on the ECHONET Lite option.
   (See <https://www.mitsubishi-electric.co.nz/wifi/learn_echonet.aspx>.)
3. Homey and the air conditioner on the same subnet. UDP port **3610** must be
   reachable; ECHONET uses multicast group `224.0.23.0` for discovery.

It is strongly recommended to give the adapter a **static DHCP reservation** in
your router so its IP address does not change.

## Installing & pairing

```bash
npm install -g homey          # if you don't have the CLI
homey login
homey app install             # install onto your own Homey
# or, for live development:
homey app run
```

Then in the Homey app: **Add device → Mitsubishi AC (ECHONET) → Mitsubishi Air
Conditioner**. The app multicasts an ECHONET discovery request and lists every
air-conditioner node it finds. If discovery doesn't find your unit (some managed
switches block multicast), add it anyway and set the **IP address** manually in
the device's *Advanced settings*.

## Project layout

```
.homeycompose/            App-level manifest + custom capability definitions
  app.json                App metadata (id, version, images, …)
  capabilities/           ac_mode, fan_speed, vane_vertical (enum pickers)
app.js                    Homey.App entry point
lib/
  EchonetLite.js          ECHONET Lite Format-1 frame build/parse, get/set, discovery (UDP/dgram)
  constants.js            EPC codes + Mitsubishi value <-> friendly mappings
drivers/mitsubishi-ac/
  driver.compose.json     Driver manifest (class, capabilities, pairing, settings)
  driver.js               Discovery during pairing
  device.js               Polling + capability listeners
app.json                  Generated by `homey app build` from the above
```

`app.json` is built from the Homey Compose sources. After editing anything under
`.homeycompose/` or `drivers/`, regenerate and validate with:

```bash
homey app build
homey app validate --level publish
```

## Protocol notes

* Frames are ECHONET Lite **Format 1**: `EHD1=0x10`, `EHD2=0x81`, 16-bit TID,
  3-byte SEOJ (`05 FF 01`, controller), 3-byte DEOJ (`01 30 01`, home AC), ESV,
  OPC, then `EPC/PDC/EDT` triplets.
* Reads use **Get** (`0x62`); writes use **SetC** (`0x61`) and await `Set_Res`
  (`0x71`). Requests are correlated by TID and retried on timeout.
* Discovery queries the node-profile object (`0E F0 01`) for the self-node
  instance list (`0xD6`) and keeps only nodes that advertise a home-air-conditioner
  instance (`01 30 ..`).

EPC/value mappings are based on the ECHONET Lite *Home air conditioner* class and
the well-documented Mitsubishi behaviour catalogued in
[`scottyphillips/mitsubishi_echonet`](https://github.com/scottyphillips/mitsubishi_echonet).

## Limitations / ideas

* Target temperature is whole-degree (ECHONET `0xB3` granularity); half-degree
  requests are rounded.
* Horizontal vane (`0xA5`) and error/special-state reporting (`0xAA`) are not yet
  surfaced.
* Placeholder app/driver artwork is generated — replace `assets/images/*.png`
  with real branding before publishing to the Homey App Store.
